# 30-day launch plan
Window: 19 October–18 November 2026. Publication is a target, not a promise.

Days 1–3: consolidate the repository, verify the three-tab personal preview, review permissions and privacy, verify signing/account ownership and create the Play developer account.
Days 4–7: physical-device testing and tester recruitment, fix blocking/timer issues, prepare real screenshots and the static privacy/support website.
Days 8–21: closed testing with the required cohort and continuous opt-in period. Keep a real feedback log and issue list. Fixes can be released to the testing track.
Days 22–26: examine feedback, test the release build, finalize Data safety/accessibility/content rating/listing. Apply for production access when eligible.
Days 27–30: submit final reviewed release and respond to Google if required. Review may extend beyond this window.

Product scope: selected-app blocking with confirmed Permanent Mode, two protection pauses per month, usage-based breaks, daily habits and the third Keep Me Out tab. Keep Me Out needs HTTPS server provisioning and user-owned recovery before public launch. The shared master-admin setup is only a personal preview. No ads, payments or remote AI in launch v1.

First 3 months after production launch: free and ad-free. Observe voluntary tester feedback and actual retention metrics only if a later privacy-reviewed measurement approach is agreed; do not silently introduce tracking.
Premium later: draft candidate features are recurring schedules, multiple focus profiles, optional local export and richer local statistics. Validate user demand before implementing billing. Keep basic blocking useful for free users.
